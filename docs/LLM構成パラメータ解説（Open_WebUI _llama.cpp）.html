LLM構成パラメータ解説（Open WebUI / llama.cpp）

① 最重要：max_tokens（出力上限）

モデルが生成できる 出力トークン数の上限 を決める設定です。

例：

max_tokens = 512 → 約512トークンで回答が打ち切られる

これを以下のように増やすことで長文生成が可能になります：

  • 2048
  • 4096
  • 8192

Open WebUIでは -1 を指定すると「無制限（サーバー側が許す範囲）」として扱われます。

Open WebUIでの設定手順

  1. チャット画面右上の Parameters を開く
  2. Max Tokens を 4096 や 8192 に変更
  3. モデルごとの Preset に保存可能

② llama.cpp の Context サイズ（-c）

コンテキストウィンドウは、以下すべてを含む「総トークン数の上限」です：

  • 入力（質問）
  • システムプロンプト
  • RAG結果
  • 回答

現在の設定は -c 2048 で、長文生成には不足しています。

例：

-c 8192 → かなり余裕がある
RTX3060なら 8192 は十分現実的
余裕があれば 16384 も可能

コンテキスト不足は以下のような現象を引き起こします：

  • 回答が途中で終了する
  • 古い会話が消える
  • RAGの内容が欠落する

③ HTTPタイムアウト（llama.cpp側）

生成が長時間かかる場合、タイムアウトにより途中で止まることがあります。

llama.cpp には --timeout があり、例：

--timeout 3600 → 1時間待つ（デフォルトは600秒）

docker-compose の例：

command:
  - --timeout
  - "3600"

④ Open WebUI側のタイムアウト

Open WebUIにもタイムアウト設定がありますが、生成停止の原因の多くは：

  • llama.cpp の --timeout
  • max_tokens の不足

モデル一覧取得用の AIOHTTP_CLIENT_TIMEOUT_MODEL_LIST とは別です。

⑤ ストリーミング（stream=true）

Open WebUIはストリーミング受信のため、生成が30分かかっても途中で止まりません。

ローカル構成では非常に有利です。

あなたの構成向け推奨設定（RTX3060 / Qwen2.5 7B）

docker-compose の例：

command:
  - -m
  - /models/qwen2.5-7b-instruct-q4_k_m.gguf

  - -c
  - "8192"

  - --timeout
  - "3600"

  - -np
  - "1"

  - --temp
  - "0.2"

  - --top-p
  - "0.9"

  - --repeat-penalty
  - "1.1"

  - --chat-template
  - chatml

Open WebUI側：

  • Max Tokens：4096〜8192

コンテキストと出力のバランス

例：

Context 8192
入力 3000
RAG 2500
回答 4096
→ 合計 9600 → コンテキスト超過 → 回答が途中で切れる

そのため：

  • Context（-c）：16384〜32768
  • Max Tokens：4096〜8192
  • Timeout：3600秒
  • Parallel（-np）：1
  • ストリーミング：有効
